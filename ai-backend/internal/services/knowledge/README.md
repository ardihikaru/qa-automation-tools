# services/knowledge

## Overview
Product knowledge base (spec: [PRODUCT_KNOWLEDGE_SYNC.md](../../../../docs/designs/PRODUCT_KNOWLEDGE_SYNC.md)). It imports a product's catalog (parts, modules, sub-modules, features, epics, user stories, test cases) from its **automation repo** `docs/` into `kb_*` tables, keeps a sync history with a diff, problems and an AI change summary, and serves the data to `/api/products/{id}/knowledge/*`.

## Interface
- `Format` (`catalog.go`): `Name()`, `Version()`, `Parse(files) (*Snapshot, []Problem, error)`; `Lookup`, `Names`, `Enums`. Registered: `test-catalog-v1` (`testcatalog.go`), a port of `automation-test-sut/scripts/test-catalog.mjs` at `521618a` (duplicates last-wins, unknown-status rows skipped, out-of-heading features kept). Version 2 also accepts a 13-column feature row with `Prod since` after `Status as of` (stored raw in `kb_features.prod_since`, parsed by `ParseProdSince` in `export_filter.go`). Version 3 also accepts 14 columns with `Periode pelaksanaan` after `Prod since` (`kb_features.dev_period`; modules/sub-modules roll it up, `devPeriodRollup`).
- Cell grammar ([KNOWLEDGE_TRANSLATION.md](../../../../docs/designs/KNOWLEDGE_TRANSLATION.md)), parser version 4: `cells()` reads a run of k backslashes before `|` as a literal pipe preceded by (k-1)/2 backslashes when k is odd, and as a delimiter (run kept) when k is even; other backslashes are literal. `<br>`, `<br/>`, `<br />` (any case) decode to LF in cells and story text. Writer side: `EncodeCell(text)` and `EncodeStoryText(text)` return the text as one cell or story text (CRLF to LF, trimmed, LF as `<br>`, `|` as 2m+1 backslashes plus pipe in a cell); they return `ErrCellText` for a control character other than LF or a literal `<br>` tag. Invariant: `cells("| "+EncodeCell(x)+" |")[0] == canon(x)` (canon = CRLF to LF, trim). Callers join cells with ` | `.
- `Syncer` (`sync.go`): `NewSyncer(db, pool, ai)`, `Start(ctx, productID, trigger, userID)`, `FailOrphanedSyncs`, `StartScheduler(ctx, interval)`. Errors: `ErrProductNotFound`, `ErrNotConfigured`, `ErrUnknownFormat`, `ErrNoAutomation`, `ErrUnavailable`, `ErrRunning{SyncID}`.
- Hooks (`sync.go`): `Syncer.OnSucceeded(productID)` runs after a sync committed, `Syncer.OnUnchanged(productID)` after a scheduled sync skipped for an unchanged commit. Set at startup before `StartScheduler`; they must return at once. `knowledge` does not import the GAOS pusher (`cmd/server/main.go` wires them to `gaossync`).
- Queries (`query.go`): `Summary`, `Tree`, `Syncs`, `Sync`, `Epics`, `Stories`, `TestCases`, `Entity`, `PutAnnotation`, `DeleteAnnotation`, `SaveDraft`, `DeleteDraft`, `ValidFormat`. Errors: `ErrNotFound`, `*InputError` (400), `*ConflictError` (409).
- Verification (`verification.go`, CASE_VERIFICATION_AND_EPIC_TAB.md): `PutVerification` (upsert/delete in `kb_case_verifications` plus an append-only `kb_case_verification_events` row, one tx), `Verifiers`, `VerificationHistory`, `verificationFilter` (`Filter.Verified`, `Filter.VerifiedBy`); test case items get `verification` in `decorate`; `Epics` adds `verified_valid/invalid`, `last_pass/fail` from one grouped query. A knowledge sync never touches these tables.
- Translation (`translate.go`, `i18n.go`, [KNOWLEDGE_TRANSLATION.md](../../../../docs/designs/KNOWLEDGE_TRANSLATION.md)): `NewTranslator(ctx, syncer, chatter, TranslatorConfig{Model, Concurrency, BatchFields, BatchChars, Pause})` (`Chatter` = `*ai.Service`: `Configured`, `ChatMessages`, `LastUsage`), `Trigger(pid)` (the `OnSucceeded` hook, returns at once), `StartRun(ctx, pid)` (forced, returns the run id; `ErrTranslationDisabled`, `*ConflictError`), `TranslationStatus(ctx, pid)`, `Enabled`, `Wait`; `Syncer.FailOrphanedTranslationRuns`. Read side: `WithLang(ctx, "en"|"id")` / `LangOf` carry the display language; with `id`, every item from `decorate` and every `refs` label gets `i18n: {lang: "id", fields: {<field>: {text, state, source_lang, model, translated_at}}}` (only fields that have a text; `state` is `machine`, `original` or `stale`). `q` (`qMatch`) matches the code, the English columns and the `kb_translations` text. `Epics(ctx, pid, includeRemoved, q)` and `Modules(ctx, pid, includeRemoved, q)` take a `q`.
- Draft ID to EN (`draft_lang.go`, KNOWLEDGE_TRANSLATION.md): `Syncer.SetDraftTranslator(*Translator)`; `StoryBody.Lang` / `TestCaseBody.Lang` (`en|id`, a hint) make `SaveDraft` send `text` / `scenario` through `Translator.draftToEnglish` (the translation model, JSON `{source_lang, text}`, one retry on an invalid reply, `Feature: "knowledge-translation"`, conversation kind `translation`) before the transaction. `id` or `mixed`: the English goes to `kb_stories.text` / `kb_test_cases.scenario` and the typed text to `kb_translations` (`state='original'`, `src_hash` of the English); `en`: stored as typed. An empty `lang` (machine callers such as the GAOS proposals) never calls the model. A failed call or invalid reply returns `*DraftTranslateError` (API 502) and saves nothing; `lang=id` with translation off returns `ErrTranslationDisabled` (503).
- Write-back, pure (`publish_render.go`): `RenderDrafts(files, RenderRequest{EpicCode, Stories, Cases, Taken}) (*Rendered, error)` allocates the next free `US-<E>-NN` / `TC-<E>-NNN` (maximum over the catalog, the epic file text and `Taken`, plus one), appends story bullets after the last bullet and case rows after the last row (links to the feature part files relative to the epic file, `EncodeStoryText` / `EncodeCell`, the file's line ends kept), then parses the result with `testCatalog.Parse` and refuses (`*GateError`, `IsGateError`) unless no new Problem appears (compared by file and message), no existing entity changed (source lines ignored) and the new stories and cases equal the drafts field by field. A draft story without features is written `(unmapped: ...)`. The epic code must be capital letters only.
- Write-back, DB (`publish.go`): `CollectDrafts` / `JobDrafts` (publishable drafts of an epic and `Blocker`s: a case with no story, or on a draft story that is not in the same publish), `TakenCodes`, `QueuePublication`, `PublicationRunning|Assign|Opened|Failed`, `ActivePublishJob`, `SyncRunning`, `LatestSyncCommit`, `Publications` (one entry per job), `JobCodes`, `MovedTo`; `ReconcilePublications(ctx, pid, PRChecker)` (`*repopool.Pool` satisfies `PRChecker`). Table `kb_publications` (one row per draft; `queued|running|pr_open|merged|failed`).
- Coverage (`coverage.go`): `CoverageBy`, `Features`, `Modules`. Assistant files (`assistants.go`): `ParseAssistants`, `KeepForSync`; `Assistants` (query.go) lists them per product or across products.
- Checklist export ([MODULE_CHECKLIST_EXPORT.md](../../../../docs/designs/MODULE_CHECKLIST_EXPORT.md)): `Syncer.ChecklistKeyInfo` (latest succeeded sync id, product name, history watermark; one small read-only transaction) and `Syncer.ChecklistSnapshot` (parts, modules, sub-modules, features and optional history in one read-only REPEATABLE READ transaction; dedicated queries, `Tree` is not reused). `RenderChecklist(snap, "pdf"|"xlsx"|"csv", withLastUpdate)` (`export_checklist.go`, `export_pdf.go`, `export_xlsx.go`, `export_csv.go`; `export_cache.go` is below) is pure and deterministic. `TemplateVersion` goes into the cache key. Errors: `ErrNoSucceededSync` (409), `ErrExportTooLarge` (413, over 20 000 features).
- Export cache (`export_cache.go`): `NewExportCache(src, store objectstore.Store, namespace, timeout)`, `Serve(ctx, pid, ExportQuery{Format, LastUpdate, Force}) (ExportResult{Body, ContentType, Filename, Cache}, error)`, `Wait()` (background Puts), `ExportBaseName` (header-safe product name), `Syncer.ProductExists`. `Cache` is `hit`, `miss`, `regenerated` or `bypass`.
- Storage (`store.go`): `apply(ctx, tx, productID, syncID, sha, firstSync, snap, prob)` (diff + batched upsert + soft delete + link-set diff + feature status history), `countActive`, `summarizeProblems`.

## Invariants
- The sync reads only through `repopool.ReadTree` (a sync-owned bare mirror); it never writes to a product clone or remote.
- One running sync per product (`kb_syncs.running_flag` unique key). Terminal status writes use a fresh context; `FailOrphanedSyncs` at startup fails `running` syncs and `pending` summaries.
- Entity rows, links, counts, diff, problems and `status='succeeded'` are written in one transaction. A catalog with no features and no test cases fails the sync (nothing is soft-deleted).
- Unchanged rows are not written; location-only changes update `source_file`/`source_line` without a diff entry. Same commit + parser version gives an empty diff (`diff.unchanged`); a scheduled sync of the same `(repo, branch, format, parser_version, commit)` is `skipped`.
- Status history ([MODULE_CHECKLIST_EXPORT.md](../../../../docs/designs/MODULE_CHECKLIST_EXPORT.md)): `apply` writes `kb_feature_status_history` rows in the sync's transaction: a feature added (`source='sync'`, or `'backfill'` in the product's first sync), restored or updated with a different `release_status` (with `prev_status`). A restore or update with the same status, a parser-version hash rewrite and a removal write nothing. Writes use `ON DUPLICATE KEY UPDATE id = id`.
- Export rendering never reads the DB or the clock; every date is converted from UTC to Asia/Jakarta (UTC+7, fixed zone). Raise `TemplateVersion` on any output change (the golden-hash test fails otherwise). Orphan rows (feature without an active module, module without an active part) are excluded and counted in `Skipped`. Date order for "status since": a `sync` history row, then `backfill` (approximate, marked `~`), then none; `status_as_of` is never used. Text cells starting with `= + - @ TAB CR` are neutralised in CSV (`'` prefix) and written as string cells in XLSX. The PDF uses core Helvetica (cp1252); other characters become `?`.
- Export cache key: `qa-automation/{namespace}/knowledge-exports/{pid}/modules-checklist/sync-{syncId}/v{TemplateVersion}/n{sha1(name)[:8]}/{plain|last-update-h{historyMaxId}}[/prod[-{from}-{to}]].{ext}` (the scope suffix only for `scope=prod`, `x` for an open end; `FilterChecklist` runs on the snapshot before rendering). `Serve` reads key info lightly first (a hit costs one small DB read and one `Get`), then generates all three formats from one snapshot under a single-flight (key without extension, plus `:force` for forced requests, so a forced request never joins an unforced flight), stores the requested format first and the other two afterwards in the background. A store error never fails the request: it is logged as `op` and `code` only and answered as `bypass` (a failed `Get`/`Stat` skips every `Put`). `force=1` is ignored (served as `hit`) when the object is younger than 30 s (a negative age counts as 0).
- Synced rows are read-only through the API; local drafts use `L-` codes and are hard-deleted. Annotations are keyed by code and survive re-syncs.
- Navigation map ([NAVIGATION_MAP.md](../../../../docs/designs/NAVIGATION_MAP.md)): `KeepForSync` also keeps `navmap.KeepRepoFile` files (`*.ts` under `src/web/`, `src/api/rest/`, `src/fixtures/`, `tests/web/`, `tests/api/rest/`). After a succeeded sync's commit (after `OnSucceeded`), and on a skipped scheduled sync when `nav_builds` is missing or has another `navmap.Version`, `buildNav` (`nav_store.go`) runs `navmap.Build` under `recover()` and replaces `nav_routes`/`nav_links` and upserts `nav_builds` in its own transaction (1 min). A failure keeps the previous inventory, records `nav_builds.status='failed'`, and never changes the sync's status; `parserVersion` is unchanged, so a skipped sync stays skipped (no catalog write, no `OnSucceeded`).
- Translation: `kb_translations` (key `(product_id, entity_type, code, field, lang)`, `lang='id'` only so far) is never written by `apply`, so a sync cannot overwrite it or change an English column. A field is translated when it has no row or `src_hash` (SHA-256 of the trimmed, NFC-normalised English text) differs; stale texts are still shown and searched. Texts: part/module/submodule `name`, feature `name`+`notes`, epic `title`+`area`, story `text`, test case `scenario`. Batches hold at most 20 fields or 6 000 characters, one call each with `ChatOpts{Model, Temperature: 0.1, Feature: "knowledge-translation", Conversation{Kind: "translation", Ref: run id}}` and a 1 s pause. The reply (`[{id, source_lang: en|id|mixed, text}]`) is rejected (invalid JSON, wrong ids, an empty text, a lost code, backtick span, `{placeholder}`, URL or capitalised Given/When/Then) and then bisected down to single fields, which go to `kb_translation_failures` (backoff 1 h, 6 h, 24 h, 24 h, give up at 5 attempts; a forced run ignores both). `source_lang=id` stores the source unchanged as `state='original'`; a fresh `original` is never overwritten by a machine run. A batch is written in one transaction and a field whose English text changed meanwhile is skipped. Two failed calls in a row (transport error, e.g. ai-manager down) end the run as `failed`. One run per product (a sync arriving mid-run schedules one more look), at most `TRANSLATE_CONCURRENCY` products at once; `OnUnchanged` does not trigger translation. Runs and token cost are in `kb_translation_runs`.
- Draft publishing: a draft with a `queued` or `running` publication answers 409 on edit and delete (`checkNotPublishing`); `pr_open` drafts are not offered again but may still be edited. The reconcile (run by `cmd/server` after `OnSucceeded`, before translation is queued) asks `PRStatus` for each open PR: `CLOSED` fails the publication (the draft is publishable again, its repo code is released); `MERGED` moves each draft whose repo code now exists as a synced row, in one transaction per PR, re-keying `kb_case_results`, `kb_case_verifications`, `kb_case_verification_events`, `kb_case_pr_links`, `kb_annotations` and `kb_translations` to the repo code, re-pointing remaining local cases of a published story, deleting the `L-` draft and marking the row `merged`; rows whose code is not synced yet stay `pr_open` for the next sync. `job_runs` and `case_approvals` keep the `L-` code; `kb_publications` keeps the mapping. A reviewer's English edit makes the moved `original` translation read as stale (hash mismatch).
- A hook never fails or delays a sync: a panic in it is recovered and logged.
- The LLM calls are the AI summary (after the commit, own 3 min timeout) and the translation runs, all through `*ai.Service` (ai-manager → claude-v3); a failure of either never fails a sync.

## Side Effects
Writes `kb_*` tables and `product_settings.knowledge_format` (via the products API); runs git through `repopool`; one LLM call per non-empty sync.
